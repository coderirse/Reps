# Reps 全面代码审查 + UI/UX 审查报告

> 审查范围：app 全部 Kotlin 源码（约 54 个文件）、构建配置、单元测试，以及 5 张实机截图（题库 / 练习面板 / 错题本×2 / 设置）。

## 总体评价

代码质量**明显高于同类个人项目**：清晰的分层（core / data / ui）、Room 外键 + 级联删除 + 索引设计完整、导入全程事务原子化、核心逻辑（Grading / PaperBuilder / WrongBookRules / CSV 解析 / 编码探测）全部 JVM 可测且有单测、构建脚本里甚至有"禁止 INTERNET 权限"的隐私门禁。架构决策（会话快照 questionIds、seeded shuffle、externalScope 兜底存盘）都有注释说明理由。

以下问题按严重程度排列，多数是"吹毛求疵"级别，但有 3 个真实的 bug/风险值得优先修。

---

## 一、代码审查：高优先级（建议尽快修）

### H1. 空题集启动练习会直接崩溃
`StudySessionRepository.createSession()` 开头是 `check(baseQuestionIds.isNotEmpty())`，而 `HomeViewModel.startPractice()` 在「收藏练习 / 错题重练」且对应集合为空时会把空列表传进去。调用链 `HomeScreen` → `scope.launch { viewModel.startPractice(...) }` 中没有 try-catch，`IllegalStateException` 会击穿协程导致**闪退**。
**修复**：在 `startPractice` 里对空 `baseIds` 返回 null/抛业务异常，由 UI 弹 Snackbar「暂无可练习的题目」；同理检查 `FavoritesScreen`、`PracticeSheet` 的错题/收藏入口是否已做前置数量校验。

### H2. 双击选项会重复计错（状态竞态）
`StudyViewModel.grade()` 的防重逻辑是先读 `perQuestion[id]?.graded` 再 launch 协程写库，但状态更新发生在**协程内部、DB 写完之后**。快速双击（或双指同点）时两次调用都通过检查 → `recordGradedAnswer` 执行两次 → `wrong_answers.wrongCount` +2，且第二次结果覆盖第一次。
**修复**：点击后**同步**先写入 UI 状态（或加 `grading: Set<Long>` pending 标记）再异步落库；或给 `grade()` 加 Mutex。

### H3. `getByIds(ids)` 的 SQLite 变量上限风险
`StudySessionRepository.getQuestions()` 用 `WHERE id IN (:ids)` 一次性传全部题目 id。minSdk 26 设备的 SQLite 默认变量上限是 **999**，用户导入 1000+ 题的题库后开一场会话即触发 `too many SQL variables` 崩溃。
**修复**：按 500 一批分片查询后合并；或把快照落成临时表/用 `orderIndex` 范围查询。

## 二、代码审查：中优先级

### M1. 深色模式判断用错数据源（真实 bug）
`QuestionCard` 用 `isSystemInDarkTheme()` 决定答对/答错的成功色，`StudyScreen` 顶部那个主题 Switch 也依赖系统值。当用户在设置里手动切到"深色"而系统是浅色时，答题卡的高亮色会用**浅色配色渲染在深色背景上**，对比度错误。
**修复**：把 `darkTheme: Boolean` 从 `RepsTheme` 层用 `CompositionLocal`（或直接 MaterialTheme.colorScheme 判断）传下去，不要在叶子节点各自调 `isSystemInDarkTheme()`。

### M2. 会计时/未计时会话的"完成"路径不对称
底部栏只有 `if (timed)` 才显示"交卷"，**未计时的会话没有任何主动完成入口**——用户做完最后一题只能按返回，会话永远停留在 ACTIVE，7 天内每次启动都会弹"恢复上次练习"。
**修复**：最后一页显示"完成"按钮（复用 submit 流程）；或答完全部题目时自动提交。

### M3. 笔记清空后残留空行
`saveNote()` 在内容为空时 `upsert(content = "")`，而不是 `delete`，数据库会积累 content 为空的笔记行，且 `StudyScreen` 里笔记图标的高亮判断 `notes.containsKey()` 会因此误判"有笔记"。
**修复**：blank 时调用 `noteDao().delete(questionId)`。

### M4. 收藏按钮取消不是乐观更新
`toggleFavorite()` 里无论新增还是取消，都先执行 `favorites + questionId`，取消分支要等 IO 完成后才从 state 里移除——点击心形取消时 UI 会有一拍"没反应"。同时两分支都无错误回滚（写库失败则 UI 与 DB 不一致）。
**修复**：按 `nowFavorite` 分别做乐观更新 + `runCatching` 失败回滚。

### M5. CSV 校验的小问题
- 单选题报错文案写"必须是 A-E"，但代码允许 `'A'..'F'`（`CsvQuestionParser.kt:105-107`），文案与逻辑不一致。
- 多选题答案里非法字母被静默 `filter` 丢弃："A,G" 会变成只剩 "A"，然后报"至少需要两个不同选项"，用户看不懂。建议报"出现非法答案字母 G"。
- `id` 列为负数/超大数不校验，会原样进 `orderIndex` 唯一索引。

### M6. `StudySessionEntity.questionIds` 注释与实现不符
注释写 "JSON array"，实际是逗号拼接字符串（`joinToString(",")`）。将来若有人按注释改成 JSON 解析会踩坑，改注释即可。

### M7. 会话计时精度
学习时长靠 5 秒轮询 + `lastTickAt` 差值累计，ON_STOP 兜底覆盖了后台场景，整体可用；但 `formatDuration` 输出 `MM:SS`，超过 99 分钟会显示 "123:45" 这类样式跳变。建议超 1 小时改 `H:MM:SS`。

## 三、代码审查：低优先级 / 打磨项

1. **无障碍**：`StudyScreen` 返回键、`HomeScreen` MoreVert 等多处 `contentDescription = null`，TalkBack 用户无法操作。仅装饰性图标才应传 null。
2. **测试盲区**：core 层覆盖很好，但 ViewModels（StudyViewModel 的模式切换、断点恢复、到期自动提交）和 Room DAO 完全没有测试。已引入 `room-testing` 依赖却没用上，建议补 MigrationTest 和一个内存库 DAO 冒烟测试。
3. **DI**：手写容器对单模块 MVP 完全够用（注释里已说明），不建议现在上 Hilt；但 `StudyViewModel.create()` 与各 `Factory` 风格不一，可统一。
4. **导入大文件**：`readAndParse` 一次性 `readBytes()`，几十 MB 的 CSV 会占双倍内存。可以流式读 + 分段探测编码，不过对目标场景（几百~几千题）影响不大。
5. **用户导入的图片不支持**：`import()` 里 `imageBasePath == null` 时静默丢弃 image 列，导入预览里最好提示"该题库含图片引用，暂不支持导入图片"，避免用户以为丢了字段是 bug。
6. **`onReciteModeChange`** 直接改 `session = s.copy(...)` 后在协程里 `session!!`，非原子；配合 H2 的并发修复顺手整理。
7. **`ExampleUnitTest` / `ExampleInstrumentedTest`** 模板文件可删。
8. **`subjectDao().deleteById`** 建议在 Snackbar 里加"撤销"（把实体暂存重插），删除题库是不可逆操作。

## 四、UI/UX 审查（基于 5 张截图）

整体是干净的 Material 3，靛蓝主色 + 中性灰卡片，风格统一、信息密度克制。主要问题集中在**错题本**和**信息可得性**。

### 4.1 错题本（最需要改的一页）

1. **卡片不可点开 = 最大交互缺失**。错题卡片只显示题干前两行 + 红色元信息，点击没有任何反应。用户来错题本的核心诉求是"看这道题为什么错"——建议点击卡片弹出/跳转题目详情（选项 + 正确答案 + 解析），或至少提供"去重练这一题"。
2. **列表从筛选 chips 底下穿过**（第 2 张截图顶部可见卡片文字被 chip 行裁切）。筛选行没有背景色/阴影，滚动内容直接从底下透出。给 header 区域加 `background(background)` 或让 chips 随列表滚走。
3. **红色用得过量**。"累计做错 1 次 · 最后做错 08-30 18:02" 整行红色，列表里一片红海。红色应只用于强调错误状态；建议：错次用红色小徽标（如 ×3），日期用 `onSurfaceVariant` 灰色。
4. **右侧对勾图标语义不明**。灰色 CheckCircle 看起来像"已完成/禁用"，实际是"标记为已掌握"的按钮，可点性几乎为零。建议：改成带文字的动作（如"标掌握"）或滑动操作，已掌握项用实心 + primary 色。
5. **多题库时无法一键重练**，Snackbar 提示"请先选择题库"是被动引导。更顺的路径：点"开始错题重练"弹出题库选择 sheet，而不是让用户先理解筛选逻辑。

### 4.2 题库首页 + 练习面板

6. **题库卡片信息太薄**。只有"390 题 · 导入于 2026-08-30"。最有价值的是**进度**：已练 x 题 / 正确率 / 上次练习时间。一张卡加一行进度条（LinearProgressIndicator）就能把首页从"文件列表"变成"学习仪表盘"。
7. **练习面板下方大面积留白**（第 4 张截图）。六个入口全是纯文字行，间距极大。建议每行加 leading 图标 + 副标题（"顺序练习 · 从第 1 题按顺序刷"），既填空间又降低理解成本；"继续上次练习"已经是卡片样式，可保持并置顶强化。
8. **首页空白态与单题库态之间缺过渡**：只有一个题库时页面下半部分全空。可以在题库列表下方放"学习统计"小卡（本周刷题数、错题数），或直接用错题本/收藏入口引导。

### 4.3 刷题页（StudyScreen）

9. **顶栏"深色" Switch 应收起**。刷题页顶栏塞了：返回、科目、进度、倒计时、"深色"文字+Switch、练习类型下拉、模式 A/B、收藏、笔记——两行工具栏太挤（第 2 行还带横向滚动）。深色开关与设置页重复且会**永久覆盖跟随系统**的偏好，建议移进右上角溢出菜单。
10. **练习类型下拉里 4 个永远禁用的菜单项**（专项/自定义/错题/收藏 `enabled = false`）会让用户以为坏了。要么只显示可切换的（顺序/随机），要么让它们跳回首页的对应入口。
11. **答对/答错缺少动效与反馈**。判定只有颜色变化，建议加一个轻震感（`HapticFeedback`）+ 图标动画（✓/✗ 浮现），背题场景的正反馈很重要。
12. **多选题确认按钮位置**。确认按钮在选项列表末尾，选项多时滚出屏幕；建议固定在底部操作栏或跟随最后一个选项。
13. **答案解析卡的"答案"用绿色**、解析用灰色，层级可以；但建议把用户的选择也显示出来（"你的答案：B"），错题回顾时更直观。

### 4.4 设置页

14. **"清除所有数据"没有破坏性样式**。它和普通条目长得一样，仅靠小字描述"操作不可恢复"。建议：红色文字 + 图标 + 二次确认对话框里要求输入/长按确认（目前只有 AlertDialog 的话至少加红色按钮）。
15. **"关于"分组里只有一行"关于"**，分组标题和条目重名。合并成一行，或把版本号、开源地址、评分入口放进这一组（现在版本信息可能在 About 页，首页分组可以显示"版本 1.0.0"增加信息量）。
16. **缺"数据备份/导出"**。用户的刷题进度、笔记、收藏全在本机且不可导出，卸载即失。哪怕先支持"导出为 CSV/JSON + 导入"，也是离线应用的重要安全网，和"清除所有数据"形成对照。

### 4.5 视觉细节

17. 卡片圆角、间距基本一致，但**页面标题（headlineMedium）下的留白节奏**各页不同（题库 16dp、错题本 16dp、设置更松），建议统一 spacing token。
18. 错题本卡片与题库卡片同为灰色，两页视觉无区分度；错题本可用 `errorContainer` 的极淡色调做卡片底色，强化"错题"语境（注意别和红字叠加过载）。
19. 底部导航 4 tab 清晰；选中态用了 M3 默认 pill，OK。图标语义（列表=错题本、心=收藏）合理。
20. 空状态组件（EmptyState）有 icon+title+description，但建议插画化或加动作按钮（错题本空状态可加"去刷题"直达）。

## 五、建议的行动顺序

| 优先级 | 事项 |
|---|---|
| P0 | H1 空题集崩溃、H2 双击重复计错、H3 IN 上限分片 |
| P1 | M1 深色判定、M2 未计时会话完成入口、错题本卡片可点开详情、错题本列表穿透修复 |
| P2 | M3~M7、红色语义、掌握按钮样式、题库卡片进度、设置页破坏性样式 |
| P3 | 备份导出、无障碍文案、VM/DAO 测试、动效打磨 |

项目底子很好，上面大部分是打磨项；把 P0 三个修掉后，这个 app 的工程质量就可以放心对外发布了。
